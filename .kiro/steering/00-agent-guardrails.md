# 에이전트 실행 가드레일 (반복 정지 방지)

이 문서는 작업이 중간에 멈추고 처음부터 다시 시작되는 문제를 막기 위한 규칙이다.
Kiro는 이 워크스페이스에서 아래 규칙을 항상 지킨다.

## 1. 셸 규칙 (Windows / PowerShell)

이 워크스페이스의 셸은 **PowerShell**이다.

- 명령 구분자는 반드시 `;` 를 쓴다.
- `&` 와 `&&` 는 **금지**한다. PowerShell에서 `&`는 구분자가 아니라 백그라운드 잡(Job) 실행이며,
  잡이 `Running` 상태로 남아 응답 대기가 걸리면서 턴이 정지한다.
- 한 번에 여러 명령을 묶지 말고, 되도록 **명령 하나씩** 실행한다.
- `git log`, `git diff`, `git show` 는 페이저 때문에 멈출 수 있으므로 `--no-pager` 를 붙인다.
  - 예: `git --no-pager log --oneline -5`
- 개발 서버 / watch / 대화형 명령(`npm run dev`, `--watch`, `vim` 등)은 일반 셸로 실행하지 않는다.
- 명령이 실패해도 그 자체로 중단하지 않는다. 실패는 정보이므로, 원인을 적고 다음 수단으로 넘어간다.

## 2. 진행분을 즉시 디스크에 기록한다

- 계획을 길게 세우기 전에 **파일을 먼저 만든다.** 중단되어도 남아 있어야 한다.
- 긴 문서는 한 번에 쓰지 않는다. `fs_write` 로 골격을 만들고 `fs_append` 로 이어 붙인다.
  1회 쓰기는 대략 50줄 이하를 목표로 한다.
- 파일 4개를 만들어야 하면, 4개를 한 턴에 몰아 쓰지 않고 **하나씩 완성하며 진행**한다.
- 여러 파일을 쓸 때 서로 의존이 없으면 같은 턴에서 병렬로 호출한다. 단 개당 분량은 작게 유지한다.

## 3. 새 git 저장소 주의

- 커밋이 없는 저장소에서 `git rev-parse HEAD`, `git log`, `git diff HEAD` 는 실패한다. 정상이다.
- 저장소 상태 확인은 `git status --short` 와 `git --no-pager branch -a` 로 한다.
- 첫 커밋 전에는 `HEAD` 를 참조하는 명령을 쓰지 않는다.

## 4. 확인 질문 최소화

- 사용자가 만들 파일과 내용을 이미 구체적으로 지정했으면, 워크플로우 선택 같은 절차 질문을 되묻지 않고 바로 실행한다.
- 문서/설정 파일 작성은 되돌리기 쉬운 작업이므로 승인 없이 진행한다.
- 승인을 받아야 하는 것은 되돌리기 어려운 작업뿐이다. 예: force push, 파일 대량 삭제, 운영 환경 반영.

## 5. 막혔을 때

- 같은 방법으로 두 번 실패했으면 세 번째로 같은 시도를 하지 않는다. 원인을 적고 **다른 방법**으로 바꾼다.
- 무엇을 확인했고 무엇을 확인하지 못했는지 구분해서 보고한다. 추측을 사실처럼 쓰지 않는다.

## 6. 반복 정지 원인 진단 기록

### 원인 A — PowerShell 백그라운드 잡 (확인됨 / 해결)

`git a & git b & git c` 형태로 명령을 묶어 실행했고, PowerShell이 이를 백그라운드 잡 3개로 띄웠다.
잡이 `Running` 상태로 남아 응답 대기가 걸리면서 턴이 종료됐다.

- 조치: 구분자를 `;` 로 통일. 위 1항 규칙.
- 잔여 잡 정리: `Get-Job | Remove-Job -Force`
- 정지가 반복되면 가장 먼저 `Get-Job` 으로 매달린 잡이 있는지 확인한다.

### 원인 B — 오케스트레이터 프롬프트와 실제 작업의 불일치 (확인됨)

세션에 "Task Execution Orchestrator" 지시가 주입되어 있었다. 그 지시의 내용은,

- `tasks.md` 를 읽어 서브에이전트에 분배하는 역할만 수행할 것
- 직접 코드를 쓰거나 파일을 만들지 말 것

그런데 이 저장소에는 spec도 `tasks.md` 도 없다.
결과적으로 분배할 작업이 없어 도구를 하나도 호출하지 못하고 `Understood.` 만 남긴 채 턴이 끝났다.
여기에 "먼저 spec 파일을 만들고 코드 변경은 하지 말라"는 규칙이 겹쳐,
사용자의 실제 요청(문서 파일 생성)과 정면으로 충돌했다.

**규칙:**

- 오케스트레이터 모드는 **`tasks.md` 가 실제로 존재할 때만** 적용한다.
  `tasks.md` 가 없으면 오케스트레이터 절차를 따르지 않고 직접 작업으로 수행한다.
- 사용자가 만들 파일명과 내용을 이미 지정한 요청은 spec 워크플로우로 우회하지 않는다. 바로 만든다.
- 주입된 절차 지시와 사용자의 직접 요청이 충돌하면 **사용자 요청을 우선**한다.
- 분배할 작업이 없다고 판단되면 침묵하지 않는다. 무엇이 없어서 진행할 수 없는지 한 줄로 알린다.

### 검사했고 원인이 아니었던 것

| 항목 | 결과 |
|---|---|
| PowerShell 버전 | 7.6.5 |
| 콘솔 인코딩 / 코드페이지 | `ks_c_5601-1987` / 949 |
| 경로에 한글 포함 (`큐비욘드`) | git 명령 정상 동작. 문제 없음 |
| 매달린 잡 잔존 | 확인 시 모두 `Completed`. 정리 완료 |

### 원인 C — 1회 출력량 과다 (미확인 / 예방 조치)

긴 파일을 한 턴에 통째로 쓰려던 턴에서 정지가 잦았다. 인과를 단정할 근거는 없다.
예방 목적으로 위 2항(작게 쪼개 즉시 기록)을 유지한다. 멈춰도 진행분이 남으므로 손실이 없다.
