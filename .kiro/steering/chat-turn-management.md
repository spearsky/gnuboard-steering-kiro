# 채팅 턴 관리 규칙

턴이 끊기거나 정지해도 작업이 손실되지 않게 하는 규약이다.
연결 끊김은 예방할 수 없으므로, **끊겨도 잃을 것이 없는 상태**를 유지한다.

## 한 턴에 하나의 산출물

- 한 턴에서 파일 하나를 완성한다. 여러 파일을 한 턴에 몰아 쓰지 않는다.
- 턴이 길어지면 정지 확률이 올라간다. 짧게 끊어 여러 턴으로 진행한다.

## 말보다 파일을 먼저

- "다음은 X를 하겠습니다" 로 턴을 끝내지 않는다. 그 턴에서 X를 실제로 디스크에 쓴다.
- 계획과 설명은 끊기면 사라진다. 파일만 남는다.
- 설명은 파일을 쓴 **뒤에** 짧게 붙인다.

## 작업 단위마다 커밋하고 푸시

- 파일 하나 완성 → `git add` → `commit` → `push`.
- 여러 파일을 다 만든 뒤 한 번에 커밋하지 않는다. 중간에 끊기면 전부 미커밋으로 남는다.
- 푸시까지 해야 원격에 남는다. 로컬 커밋만으로는 작업 머신 밖에서 복구할 수 없다.

## 재개할 때는 기억이 아니라 디스크를 믿는다

```powershell
git status --short
git --no-pager log --oneline -5
```

그다음 **대상 파일을 읽어 어디까지 작성됐는지 확인한 후** 이어 쓴다.

- 이어 쓸 때는 `fs_append` 또는 `str_replace` 를 쓴다.
- 확인 없이 `fs_write` 를 쓰면 기존 내용을 덮어써 진행분을 날린다.

## 침묵하지 않는다

- 진행할 수 없는 상태(선행 파일 없음, 정보 부족)면 한 줄로 무엇이 없는지 알린다.
- 아무 도구도 호출하지 않고 `Understood.` 같은 빈 응답으로 턴을 끝내지 않는다.

## 셸 왕복 최소화

- 셸 호출이 늘어날수록 정지 지점이 늘어난다.
- 상태 확인용 명령을 습관적으로 반복하지 않는다. 파일 확인은 읽기 도구로 한다.
