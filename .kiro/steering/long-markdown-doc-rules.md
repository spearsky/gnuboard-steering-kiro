# 긴 마크다운 문서 작성 규칙

긴 문서를 한 번에 쓰려는 시도가 턴 정지의 주요 원인이다. 반드시 쪼개서 쓴다.

## 분할 원칙

- **1회 쓰기 40~60줄.** 이 범위를 넘기면 나눈다.
- `fs_write` 로 골격(제목 + 앞 섹션)을 만들고, 이후는 `fs_append` 로 이어 붙인다.
- 섹션 경계에서 나눈다. 코드블록 중간에서 끊지 않는다.
- 문서 하나가 200줄을 넘길 것 같으면 처음부터 여러 파일로 분리할지 검토한다.

## 작성 순서

1. `fs_write` — frontmatter + 제목 + 목차/개요 + 첫 섹션
2. `fs_append` — 섹션 단위로 추가 (한 턴에 1~2회)
3. 문서 완성 후 커밋 + 푸시

## 이어 쓸 때

- **먼저 파일을 읽어 마지막 줄을 확인한다.** 어디까지 썼는지 추측하지 않는다.
- 이어 쓰기는 `fs_append`. `fs_write` 는 덮어쓰기이므로 이어 쓰기에 쓰지 않는다.
- 중간 섹션을 고칠 때는 `str_replace` 를 쓴다.

## 코드 예제

- 코드블록은 언어를 명시한다: ` ```php `, ` ```css `, ` ```powershell `
- 예제 하나가 40줄을 넘으면 핵심만 남기고 줄인다. 전체 파일을 붙여넣지 않는다.
- 예제 안 경로/이름은 플레이스홀더로 통일한다. 예: `{project}`

## 표

- 열이 5개를 넘으면 표를 쪼개거나 목록으로 바꾼다. 가로로 넘치면 읽을 수 없다.
- 표 안에 코드블록을 넣지 않는다. 인라인 코드까지만 쓴다.

## 물결표 주의

- 범위 표기에 `~` 를 쓸 때 `768~1199px` 처럼 공백 없이 붙여 쓴다.
- `~text~` 형태로 양쪽을 감싸면 취소선으로 렌더링된다. 범위 표기가 의도치 않게 취소선이 되지 않도록
  필요하면 `768-1199px` 또는 인라인 코드로 감싼다.
