# gnuboard-steering-kiro

그누보드5 기반 **기업용 웹사이트를 반복 제작**할 때 Kiro가 참고하는 steering 파일 모음이다.
`yesfa.co.kr` 프로젝트에서 정리된 패턴을 재사용 가능한 형태로 문서화했다.

## 이 레포는 무엇인가

기업 사이트 제작은 매번 비슷한 흐름을 반복한다.
정적 HTML을 퍼블리싱하고, 그누보드5 스킨으로 변환하고, 상담/문의를 처리할 커스텀 관리자를 붙이고, FTP로 올린다.
매번 같은 판단을 다시 하지 않도록 그 흐름과 규칙을 steering 문서로 고정한 것이 이 레포다.

## 대상 환경

| 항목 | 값 |
|---|---|
| CMS | 그누보드5 v5.6.32 |
| 런타임 | PHP + MySQL |
| 호스팅 | 국내 공유호스팅 (SSH/Composer/빌드도구 없음 가정) |
| 배포 | FTP 수동 업로드 |
| 게시판 스킨 | `g5-custom/skin/board/{project}/` |
| Q&A 스킨 | `g5-custom/skin/qa/{project}/` |
| 상담 상태 | 접수중 / 접수완료 / 답변중 / 답변완료 (`qa_status`) |
| 비회원 문의 | 허용 (`qawrite.php` 로그인 체크 비활성화) |

## 수록 문서

| 파일 | 내용 |
|---|---|
| `steering/gnuboard-project-guide.md` | 프로젝트 구조, 호스팅 환경, DB 테이블, 커스텀 관리자, 진입점 연결, 그누보드 상수/변수 |
| `steering/publishing-standards.md` | HTML/CSS/JS 퍼블리싱 표준, 네이밍 규칙, 반응형, 애니메이션 규칙 |
| `steering/skin-conversion-rules.md` | HTML → PHP 스킨 변환 규칙 (공지 목록/상세, Q&A 문의) 코드 예제 |

세 문서 모두 frontmatter에 `inclusion: manual` 이 설정되어 있다.
항상 로딩되지 않으며, 채팅에서 `#` 컨텍스트로 직접 불러서 쓴다.

## 새 프로젝트에 적용하기

```
1. 이 레포의 steering/ 파일을 새 프로젝트의 .kiro/steering/ 으로 복사
2. 문서 안의 {project} 를 실제 프로젝트 식별자로 치환
3. 채팅에서 #gnuboard-project-guide 등으로 필요한 문서를 불러서 작업
```

## 새 프로젝트 시작 워크플로우 (10단계)

### 1단계 — 프로젝트 정의 및 사이트맵 확정

프로젝트 식별자(`{project}`, snake_case)를 먼저 정한다. 스킨 폴더명, CSS 클래스 접두사, 커스텀 관리자 경로에 모두 쓰인다.
사이트맵(메뉴 depth), 페이지 목록, 게시판 목록, 문의 폼 필드를 문서로 확정한다.
게시판/문의 필드는 나중에 바꾸면 DB 스키마와 스킨을 동시에 손봐야 하므로 이 단계에서 못 박는다.

참고 문서: `steering/gnuboard-project-guide.md`

### 2단계 — 정적 HTML 퍼블리싱

디자인 시안을 정적 HTML/CSS/JS로 먼저 완성한다. 그누보드를 섞지 않는다.
`reset.css` → `page.css` → `sub.css` → `board.css` → `animation.css` 순서로 로드하고,
JS는 `page_script.js`, `sub_script.js`, `animation.js` 로 나눈다.
PC(1200px+) 기준으로 만들고 태블릿(768~1199px), 모바일(~767px)로 좁혀 내려간다.

참고 문서: `steering/publishing-standards.md`

### 3단계 — 그누보드5 설치 및 기본 설정

그누보드5 v5.6.32를 내려받아 로컬 또는 호스팅에 설치한다.
`data/` 퍼미션(707), DB 접속 정보, 기본 환경설정(사이트명, 관리자 계정)을 잡는다.
`data/dbconfig.php` 는 절대 커밋하지 않는다.

### 4단계 — 프로젝트 전용 디렉터리 구성

그누보드 루트에 `g5-custom/` 을 만들고 프로젝트 산출물을 모두 이 안에 둔다.
그누보드 코어 파일을 직접 수정하지 않는 것이 원칙이다. 코어를 고쳐야 하면 수정 이력을 남긴다.

```
g5-custom/
├── css/  js/  img/
├── inc/          # head/tail 공통 레이아웃, 상수 정의
├── skin/board/{project}/
├── skin/qa/{project}/
└── adm/          # 커스텀 관리자
```

### 5단계 — 공통 레이아웃 이관

퍼블리싱한 HTML의 head/헤더/푸터를 `g5-custom/inc/head.php`, `tail.php` 로 분리한다.
경로는 하드코딩하지 않고 `G5_URL` 및 프로젝트 상수(`PRJ_URL`)로 출력한다.
정적 페이지를 이 레이아웃 위로 옮겨 붙여 사이트 전체가 뜨는지 먼저 확인한다.

### 6단계 — 게시판 스킨 변환

공지사항 등 일반 게시판을 `g5-custom/skin/board/{project}/` 로 변환한다.
`list.skin.php`, `view.skin.php`, `write.skin.php` 가 최소 구성이다.
퍼블리싱 마크업을 유지한 채 반복 영역만 PHP 루프로 치환한다.

참고 문서: `steering/skin-conversion-rules.md`

### 7단계 — Q&A(문의) 스킨 변환 및 비회원 허용

`g5-custom/skin/qa/{project}/` 에 문의 스킨을 만든다.
비회원 문의를 허용하기 위해 `bbs/qawrite.php` 의 로그인 체크를 비활성화한다.
이때 이름/연락처/이메일을 폼에서 직접 받고, **캡차와 개인정보 수집동의를 반드시 함께 넣는다.**
로그인 체크를 풀면 스팸에 그대로 노출되므로 캡차는 선택이 아니다.

### 8단계 — qa_status 확장 및 커스텀 관리자 구축

기본 그누보드의 `qa_status` 는 미답변/답변완료 2단계다.
이를 4단계(접수중 0 / 접수완료 1 / 답변중 2 / 답변완료 3)로 확장한다.
`g5-custom/adm/` 에 상담목록과 게시판관리 화면을 만들고, 관리자 메뉴에 연결한다.
모든 커스텀 관리자 파일 최상단에서 `$is_admin` 권한 검사를 한다. 빠뜨리면 상담 개인정보가 그대로 열린다.

### 9단계 — 점검

- 반응형 3개 구간 실제 기기 확인
- 문의 등록 → 관리자 상태 변경 → 목록 반영 전체 흐름
- 비회원 문의 스팸 차단 동작
- 관리자 페이지 비로그인 직접 접근 차단
- `data/` 디렉터리 외부 노출 여부

### 10단계 — FTP 배포 및 인계

FTP로 업로드한다. 공유호스팅에는 빌드 과정이 없으므로 올리는 것이 곧 배포다.
`data/dbconfig.php`, `data/` 캐시, 로컬 설정은 업로드 대상에서 제외한다.
배포 후 관리자 계정, 게시판 설정 위치, 상담 상태 운영 방법을 문서로 정리해 인계한다.

> 공유호스팅 + FTP 배포는 롤백 수단이 없다. 덮어쓰기 전 원본을 반드시 내려받아 백업한다.
