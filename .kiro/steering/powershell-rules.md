# PowerShell 실행 규칙

이 워크스페이스의 셸은 PowerShell 7 / 코드페이지 949(`ks_c_5601-1987`)다.

## 금지

- `&`, `&&` 를 명령 구분자로 쓰지 않는다. PowerShell에서 `&`는 백그라운드 잡 실행이며,
  잡이 `Running` 으로 남아 응답 대기가 걸리면서 턴이 정지한다.
- `echo` / `Set-Content` / 히어독으로 문서 본문을 쓰지 않는다.
- 개발 서버, watch, 대화형 명령을 일반 셸로 실행하지 않는다.

## 필수

- 명령 구분자는 `;` 를 쓴다.
- 한 호출에 명령 하나. 꼭 묶어야 할 때만 `;` 로 최소한만 묶는다.
- `log` / `diff` / `show` 는 `--no-pager` 를 붙인다. 예: `git --no-pager log --oneline -5`
- 문서 본문은 `fs_write` / `fs_append` 로 파일에 직접 쓴다. 셸을 경유시키지 않는다.
- 커밋 메시지는 한글/영문 모두 동작한다. 한 줄로 짧게 쓴다.

## 터미널 출력 노이즈 (확인된 현상)

셸을 호출하면 출력 앞에 잘린 창 제목 문자열이 섞여 나올 수 있다.

```
dministrator: C:\Program Files\PowerShell\7\pwsh.exe\
```

확인된 사실:

- 명령 개수, 인자의 한글 포함 여부와 **무관**하다. 단일 ASCII 명령에서도 발생한다.
- exit code는 `0` 이고 명령 자체는 정상 수행된다. git 커밋/푸시도 성공한다.
- 다만 이 노이즈가 **실제 출력을 삼킬 수 있다.** 출력이 비어 보이는 것을 실패로 오판하지 않는다.

대응:

- 상태 확인은 셸 대신 읽기 도구(`read_file`, `grep_search`, `list_directory`)를 우선한다.
- 셸 출력이 중요하면 파일로 리다이렉트한 뒤 읽는다.
  예: `git status --short > .git/tmp_status.txt`
- 출력이 비었을 때는 실패로 단정하지 말고 별도 수단으로 결과를 확인한다.

## 정지 의심 시 점검

```powershell
Get-Job
Get-Job | Remove-Job -Force
```

매달린 잡이 있으면 정리한다.

## 새 저장소 주의

커밋이 없는 저장소에서 `HEAD` 참조 명령(`git rev-parse HEAD`, `git log`, `git diff HEAD`)은 실패한다.
첫 커밋 전 상태 확인은 `git status --short` 로 한다.

## 참고

아래는 검사했고 문제가 아니었던 항목이다. 정지 원인으로 다시 의심하지 않는다.

| 항목 | 결과 |
|---|---|
| 경로에 한글 포함 (`...\큐비욘드\...`) | git 명령 정상 동작 |
| 한글 커밋 메시지 | 커밋 성공, `git log` 출력도 정상 |
| 콘솔 코드페이지 949 | 명령 수행에 영향 없음 |
| 잔존 백그라운드 잡 | 확인 시 모두 `Completed`. 정리 완료 |
